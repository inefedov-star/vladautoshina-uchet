# Своя товароучётная система ВладАвтоШины · ТЗ и план

Решение принято 31.10.2026: пишем свою систему вместо CloudShop,
поэтапно, CloudShop работает параллельно до полной сверки.

## Зачем своя, а не готовая

CloudShop не умеет того, что нужно именно этому магазину:

- карточка шины как набор полей (ширина, профиль, диаметр, сезон, шипы,
  индексы, XL, бренд, модель), а не одна строка названия;
- шиномонтаж в системе, а не в бумажной тетради;
- ответственное хранение товара поставщика (сейчас — «Закупка» и
  «Возврат закупки» как костыль) с автоматическим расчётом 5% с выдачи;
- шинный отель: договоры, адресные ячейки (Б-04-2), сроки, продления;
- клиентская база: 75% чеков сейчас обезличены;
- витрина для консультации в магазине с живым наличием;
- отчёты, которые весь 2026 год собирались вручную в Excel.

## Решения

**История не переносится документами.** Старт с остатков на дату ввода.
Прошлые годы — сводные таблицы «товар × год» (штуки, выручка,
себестоимость, прибыль).

**Касса — Эвотор, чеки уходят в ofd.ru.** Продажа оформляется в нашей
системе, чек пробивается на Эвоторе, чеки забираются из ofd.ru и
сверяются с продажами. Прямая интеграция с Эвотором — этап 5.

**Роли:** собственник (всё), сотрудник (не видит закупку, себестоимость,
прибыль, маржу и финансовые отчёты), витрина (только розничные цены
и наличие, без входа).

**Оборудование:** сканер штрихкодов и принтер этикеток есть.
Планшет для витрины — Android, в магазине есть Wi-Fi.

**Шиномонтаж — отдельный бизнес со своим результатом:**
выручка по работам; 30% выручки — шиномонтажнику; текущие расходы;
капитальные расходы отдельно; итог по месяцам и годам.
Сейчас ведётся в бумажной тетради — нужен ввод по фото страницы
(распознавание → проверка → разнесение).

## Технические решения

**Пересмотрено 02.11.2026.** Пульт шиномонтажа на PHP + SQLite на хостинге Джино
показал себя: работает, обновляется заменой файлов, ничего не стоит сверху.
Товароучёт строим там же и в том же приложении, с тем же входом. Таблица ниже —
исходный план, оставлена для истории; при росте нагрузки данные переносятся
выгрузкой (`api.php?a=export`).

| Что | Выбор | Почему |
|---|---|---|
| Язык и каркас | Python + Django | Пользователи, права, миграции, админка из коробки |
| База данных | PostgreSQL | Деньги и остатки без потерь |
| Интерфейс | Django-шаблоны + htmx | Без сборки фронтенда; ПК, планшет, телефон |
| Код | Этот приватный репозиторий | История, откат, работа из любого чата |
| Сервер | VPS в России (Timeweb / Selectel), Docker | ~600–1500 ₽/мес |
| Резервные копии | Ежедневный дамп во внешнее хранилище | С первого дня боевой работы |

Распознавание тетради через API нейросети внутри системы — под вопросом
(доступность сервисов из РФ). Рабочий путь сразу: фото страницы
присылается Claude в чат проекта, Claude отдаёт файл, система импортирует.

## Принципы учёта

1. **Остаток — сумма движений.** Каждый документ пишет строки движения.
2. **Проведённый документ не редактируется молча** — только отмена
   проведения с записью, кто и когда.
3. **Себестоимость средневзвешенная**, как в CloudShop.
4. **Несколько складов:** «Магазин», «Ответственное хранение
   (поставщик)», позже новые точки. Чужой товар не входит в стоимость склада.
5. **Деньги отдельно от товара:** у продажи есть оплаты
   (наличные, карта, перевод, безнал).

## Витрина

Продавец и клиент вместе смотрят на планшете, что есть, как меню.
Разделы: шины (размер, сезон, шипы/липучка), диски (тип, диаметр,
разболтовка), АКБ (тип, полярность, ёмкость), крепёж (вид, резьба),
прочее — списком с поиском. Цена за штуку и за комплект, остаток
округлённо («8+ шт.»).

**Никогда не показывает:** себестоимость, закупку, маржу, поставщика.

**Фото — по модели, а не по размеру:** ~500 размеров шин в наличии
это ~300 моделей. Собираем один раз, храним в системе.

**Порядок:** прототип из выгрузки CloudShop (`vitrina/`) → после
этапа 1 живые остатки системы → позже публично на vladautoshina.ru/magazin/.

## Этапы

- **Этап 0 — Шиномонтаж.** Работы, расходы (текущие/капитальные),
  30% мастеру, отчёт по месяцам и годам, ввод по фото тетради,
  оцифровка прошлых тетрадей.
- **Этап 0б — Витрина.** Прототип готов; дальше — фото моделей,
  размещение на сервере.
- **Этап 1 — Ядро товароучёта в теневом режиме.** Справочник с полями,
  импорт карточек/остатков/контрагентов и сводной истории, документы,
  отчёты, этикетки. Результат: неделя документов в обеих системах —
  остатки и прибыль совпали.
- **Этап 2 — Рабочее место продавца.** Быстрая продажа, ответхранение
  с 5%, сверка с чеками ofd.ru.
- **Этап 3 — Клиенты и шинный отель.**
- **Этап 4 — Закупки и аналитика** (потребность, бонус Ikon 4%, мёртвый сток).
- **Этап 5 — Интеграция с Эвотором.**
- **Этап 6 — Переезд и отключение CloudShop.**
